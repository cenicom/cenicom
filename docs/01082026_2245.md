Próximo paso recomendado

En lugar de crear el End-to-End inmediatamente, propondría un bloque intermedio:

CN-NAV-004.3.1 — ServiceProvider Integration

Objetivo:

Registrar NavigationAutoDiscovery.
Registrar NavigationDiscoveryRegistrar.
Eliminar registros duplicados.
Conectar el boot() con el nuevo flujo.
Retirar la infraestructura antigua (ManifestFinder, ManifestDiscoveryService, etc.) si ya fue reemplazada.

Una vez ese bloque esté en verde, sí tendría sentido construir NavigationEndToEndTest, porque validaría exactamente el flujo que ejecuta la aplicación y no una implementación paralela.

Mi recomendación es no avanzar con NavigationEndToEndTest hasta completar esa integración del ServiceProvider, ya que así la prueba certificará el comportamiento real del sistema.
