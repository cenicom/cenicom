Mi recomendación arquitectónica para CENICOM es que las clases de definición sean únicas en el registro global. Esto haría que una carga repetida no duplique las definiciones y que el bootstrapper no ejecute dos veces la misma clase.

Sin embargo, esa decisión implica cambiar el contrato que hoy expresa test_returns_registered_definitions(), que espera dos entradas para la misma clase.

Si confirmas que cada clase de definición debe ejecutarse una sola vez, el siguiente paso será ajustar primero las pruebas contractuales del registro y del cargador; después implementaremos la corrección mínima y ejecutaremos las pruebas correspondientes.
