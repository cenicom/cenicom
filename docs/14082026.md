10.5.13 — ModuleBootstrapReporter

Vamos a ejecutarla en este orden, sin abrir todavía la integración modular de Navigation/Permissions:

Corregir el contrato

public function moduleSkipped(
    ?ModuleDefinition $definition,
    string $reason
): void;
Actualizar NullModuleBootstrapReporter para reflejar ?ModuleDefinition.
Inyectar ModuleBootstrapReporterInterface en ModuleBootstrap.

Integrar los cuatro eventos:

moduleDiscovered()
moduleLoaded()
moduleSkipped()
moduleFailed()
No eliminar ni modificar ModuleBootstrapReport: Reporter y Report tienen responsabilidades diferentes.
Añadir la certificación específica en ModuleBootstrapTest:
discovered
loaded
skipped
failed
múltiples módulos
Ejecutar primero las pruebas focalizadas.
Si todo queda verde, ejecutar la suite completa.
Criterio de cierre

Al terminar 10.5.13 debe quedar garantizado:

ManifestFinder
      │
      ▼
  DISCOVERED ─────────────► Reporter
      │
      ▼
 ModuleBootstrapPipeline
      │
      ├── SUCCESS ────────► LOADED
      │
      ├── SKIPPED ────────► SKIPPED
      │
      └── FAILURE ────────► FAILED

Y ninguna de estas responsabilidades debe pasar a Navigation ni a Security todavía.

El siguiente paso práctico es modificar primero ModuleBootstrapReporterInterface + NullModuleBootstrapReporter, y después tocar ModuleBootstrap.
